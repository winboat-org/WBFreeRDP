# Follow-up fixes from the WinBoat issue audit

2026-09-09. All ten shortlisted areas were investigated. Five demonstrated source defects were repaired as patches 20–24. **This does not mean every linked tracker issue is resolved.** The full 24-patch tree passed 30 local build/test groups; release and debug clients built successfully. Reapplying the series to pristine FreeRDP 3.30.0 produced a byte-for-byte match across 2,940 files.

## New changes

| Patch | Defect and resulting behavior | Verification |
|---|---|---|
| 20 | Several X11 MIME formats map to Windows CF_DIB. The client previously selected the first mapping, even if the current clipboard owner offered only PNG or a BMP alias. Selection now respects the owner's advertised TARGETS. | 11 source-derived X11/ASan/UBSan checks pass; the 19-patch control fails 8. Live host PNG, BMP and BMP-alias transfers have identical expected pixels in the Windows clipboard, including on the final release binary. A 1024×768 BMP transferred all 2,359,336 bytes with the expected decoded pixel hash. |
| 21 | `is_transient` stayed set after a tool/popup became a normal window. Initial and updated resize frames were also synchronized before classifying the style. Recompute the classification first and size the frame before mapping. | 13 source-derived sanitizer checks pass; the 19-patch control fails 9. Includes both transition directions, initial mapping, pending geometry, and 1,000 unchanged-style iterations. This alone did not stop Paint.NET dialog drift. |
| 22 | XI2 raw valuators are packed by set mask bits. A vertical-only event's first value was read as though it were its second value. Consume the packed values in order, and stop reading a target-window field that raw events do not have. | 10 sanitizer checks pass; the control fails 4. Includes both axes, single axes, additional valuators, empty masks and inactive relative-input paths. This does not enable relative input in RemoteApp or change the Wayland client. |
| 23 | Left/top clipping added the absolute window position instead of subtracting the distance outside the desktop. Account for the desktop's nonzero left/top edge. | 36 source-derived translation-invariance checks pass; the control fails 14. At desktop top 30, a window at y=20 with height 400 now clips to 390 rather than growing to 420. This is not a complete multimonitor pointer-origin fix. |
| 24 | Fixed-size Windows dialogs can include invisible borders in tracking limits that are absent from the RAIL visible window. Publishing the outer minimum as an X11 minimum forced the WM to resize the dialog, creating a geometry feedback loop. Publish interactive tracking constraints only for windows with WS_SIZEBOX. | Real X11 property checks cover fixed/resizable transitions and preserve valid/invalid maximum handling. Paint.NET Layer Properties repeatedly drifted seven pixels per correction before this patch. Three fresh fixed captures, including the final release build, kept the same native rectangle for ten seconds each. |

### Paint.NET reproduction

Used the official portable **Paint.NET 5.1.12** x64 package; the older 5.1.9 asset was unavailable. The downloaded archive SHA-256 was `d5ae7043f2fb9d365b48dfe243a2aca1c74924de99b04b6445916c95354aefa3`. The fixture opens Layer Properties with F4 in the existing interactive guest session and samples native window rectangles every 250 ms. It does not log off or reboot Windows.

The trace showed Windows outer size **316×244**, RAIL visible size **302×237**, and zero advertised resize margins for this nonresizable dialog. The WM enforced the larger X11 minimum; subsequent Windows responses advanced x by seven pixels. Reopening under the four preliminary fixes still reproduced this. Patch 24 removed the forced minimum for this dialog and stopped the loop. The final release capture held native bounds `[802,395,1118,639]` throughout every sample where the dialog existed. This establishes the Paint.NET workflow on the tested KDE Wayland/XWayland host, not every compositor or application in the geometry cluster.

| Private formats [#751](https://github.com/winboat-org/winboat/issues/751) | A registered private format survived clipboard synchronization both with and without companion Unicode text. Both payload hashes matched. StriePlan CAD's actual copy/paste workflow was not reproduced, so there is no new private-format patch or closure claim. |
| Dialog geometry [#226](https://github.com/winboat-org/winboat/issues/226), #407, #393, #669; historical #123/#247/#437 | Paint.NET Layer Properties drift is reproduced and repaired by patch 24. | Multimonitor [#289](https://github.com/winboat-org/winboat/issues/289), #730/#743/#282/#79 | Patch 23 fixes nonzero-origin clipping. The pointer path still translates RemoteApp input to X root coordinates without the full selected-desktop origin conversion. A blanket primary-monitor shift is unsafe when primary origin differs from the selected monitors' bounding origin. No complete multi-output/fractional-scale fix was published. See upstream [PR12598](https://github.com/FreeRDP/FreeRDP/pull/12598). |
| Stacking [#257](https://github.com/winboat-org/winboat/issues/257), #683/#657 | Confirmed tool/noactivate and some popup styles become `override_redirect` windows. Globally disabling override-redirect would alter menu focus behavior and was not adopted. |
| Transparent input [#509](https://github.com/winboat-org/winboat/issues/509) | X11 visual alpha and bounding regions do not establish alpha-aware click-through. Reviewed code updates ShapeBounding, but supplies no separate ShapeInput mask. Desktop Mate itself was not reproduced. |
| Selective drag [#634](https://github.com/winboat-org/winboat/issues/634) | The final release native fixture received 2 left-button downs, 2 ups and 40 moves, all under capture, through the actual Wayland pointer via a bounded dotool process. An earlier XTest attempt delivered no guest input and is not counted as an application failure. Photoshop's tool-specific failure remains unconfirmed. |
| Relative motion [#805](https://github.com/winboat-org/winboat/issues/805) | Patch 22 repairs the packed XI2 axis defect. `xf_generic_RawMotionNotify_` still explicitly rejects RemoteApp mode; the native Wayland client is outside this X11 patch. No claim of complete 3D camera compatibility. |
| Dynamic layouts [#245](https://github.com/winboat-org/winboat/issues/245) | With the existing Unicode path, a real Xlib context survived US → German → US group changes and emitted `yzy` from the same physical key. Scancode mode continued emitting the same scan code, as expected. Host alphabetic switching does not activate a guest input language or implement Japanese IME conversion keys. No new dynamic-layout patch. |
| Failed-connect cleanup [#765](https://github.com/winboat-org/winboat/issues/765) | The final binary exited early refused/accepted-then-closed loopback connections with clipboard enabled and disabled: 4 cases, no assertions or new mounts. These failures occur before authenticated clipboard/FUSE initialization. They do not reproduce or rule out the reported later teardown assertion; no speculative teardown patch. |

## Reproduction and evidence

Run `scripts/run-local-regressions.py` and `scripts/verify-patch-series.py` in the documented lab environment. New automated tests are `test-clipboard-targets.py`, `test-transient-frame.py`, `test-raw-motion.py`, `test-workarea-clip.py`, `test-fixed-dialog-hints.py` and `test-dynamic-keyboard.py`. `issue_source.py` reconstructs the 19-patch control from the pristine archive and the first 19 public patches; tests compare that control with the current production source, rather than generating the desired fix inside a test.

The existing maximum-size tests still pass all 14 cases after patch 24. All earlier local regressions, including composition, focus handoff, resize scheduling, rendering, clipboard transfer and reconnect contracts, pass. The earlier 20-minute reconnect soak, full Explorer focus matrix, CapCut maximize matrix and D3D11 matrix were not all repeated for patches 20–24.

`issue-fixes-results.json` contains the selected portable result summaries. Raw traces, binaries, downloads, host clipboard backups, credentials and guest-specific launch metadata stay outside the published repository. Clipboard probes use deterministic fixture contents and restore the captured text clipboard. Live helper tasks are bounded and removed after use. These tests used the manually selected custom client; normal WinBoat launch configuration and the system FreeRDP package were not replaced.
